# LU4 RB: согласованные решения

## Продукт
- Отдельный проект для кланов-конкурентов. Первый сервер Gamma.
- Источник статических данных — MasterWork Wiki, раздел LU4 Gamma. Общий справочник можно переиспользовать между LU4-серверами; наблюдения и правила респауна привязаны к серверу.
- Основной экран — карта с точками, списком целей и карточкой возможного дропа.
- Таймер считается **только от ручного времени убийства**. Бот не создаёт убийства.
- Результат проверки: alive / not_found / failed. Свежесть, источник и время всегда видимы. Окончание окна не подтверждает появление.
- Несколько точек на босса; отсутствие подтверждается только при корректной проверке нужной зоны.
- Оператор запускает IKAR на своей машине; самостоятельный запуск кланом поддерживается архитектурой.
- Одна лицензия IKAR обслуживает два клиента одной машины (со слов владельца).

## Приватность и монетизация
- Ручные убийства, их история и клановые наблюдения никогда не передаются конкурентам.
- Владелец данных агента не равен тому, кто запускает агент: оператор может запускать приватный клановый агент.
- NULL owner_clan_id обозначает флот сервиса. Доступ выдаётся отдельным grant: клан, сервер, боссы, агенты, срок.
- Основной пакет: сайт + разведка сервиса. Альтернатива: сайт + свои агенты. К альтернативе можно докупить разведку сервиса.
- Права просмотра, отметок убийств, агентов, участников и подписки независимы.
- Цены НЕ утверждены. $49/$15 обсуждались как гипотезы пилота, а не окончательные тарифы. В коде цен нет.
- Общая очередь сервиса не зависит от приватных убийств кланов. Управление собственными агентами отдельно.

## Техническая основа
React + TypeScript + Vite; чистое доменное ядро; PostgreSQL для следующего этапа API.
Развёртывание отдельно от LU4 Market. В v0.2 есть API с временными bearer-сессиями и PostgreSQL RLS. Пользовательский логин, приём платежей и запуск IKAR ещё не реализованы.
Все демонстрационные данные синтетические, хранятся в памяти и явно помечены.

## Открытые вопросы
1. Подтверждённые команды IKAR для выбора аккаунта/персонажа и проверки загрузки мира.
2. Покрытие РБ и фактическая длительность обхода двух клиентов.
3. Утверждённые правила респауна и поведение при рестарте сервера.
4. Способ авторизации, платёжный провайдер и канал уведомлений.
5. Изображение карты, калибровка координат и полнота справочника.

## Уточнения 19 октября 2026
- Оператор выбирает подключённые аккаунты и персонажей; каждый выбранный персонаж заранее стоит возле назначенного РБ. Пароли остаются локально.
- Два клиента обходят выбранные слоты по кругу. Автоматический вход между аккаунтами и инвентаризация аккаунтов ещё требуют подтверждения IKAR.
- Мёртвый персонаж способен наблюдать: characterAlive — диагностика, а не критерий достоверности. Загрузка мира, позиция и полное покрытие для not_found остаются обязательны.
- При известном ручном убийстве проверки пропускаются до минимального времени респауна. Неизвестное правило/убийство не приостанавливает обход.
- Свой флот клана использует только таймеры этого клана. Общий флот может использовать приватное пространство оператора. Косвенная заметность пауз по давности наблюдений принята пользователем.
- Подписчики не видят ошибки/очередь/аккаунты общего флота. Пропуск никогда не создаёт наблюдение. Telegram и Discord нужны оба.
- Оператор должен иметь явный административный доступ к кланам; клиентские пространства изолированы друг от друга. Эта административная роль ещё не реализована.
